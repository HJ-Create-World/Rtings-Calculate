# 数据架构与规则版本方案

状态：设计稿，按“离线优先、联网落库、历史可复用”的目标制定。

## 1. 目标

1. 离线可用：无网络时仍能录入、计算、查看图表和导出。
2. 联网落库：联网时把评测数据、规则版本和输入快照保存到服务端。
3. 历史复用：历史机型可与新品对比，可回看当时的规则与结果。
4. 版本可回档：规则修改可发布新版本，历史评测不被动改写。

## 2. 本地层

| 数据 | 位置 | 用途 |
|---|---|---|
| 当前评分草稿 | 浏览器 `localStorage` | 离线录入、刷新恢复 |
| 历史机型库 | 应用内置 JSON / 后续本地缓存 | 离线对比与演示 |
| 规则版本 | 应用内置 JSON / 后续本地缓存 | 当前计算与追溯 |

本地层规则：

- 草稿保存 `ruleVersion`，切换规则版本时必须提示。
- 历史评测一旦正式保存，不允许覆盖原始输入。
- 离线期间可创建待同步队列。

## 3. 云端层

后续接入后端时，建议按以下实体建模：

```text
Product        产品：品牌、型号、上市年、尺寸段
Evaluation     评测：产品、测试日期、工程师、备注、ruleVersion、status
EvaluationItem 评测输入：评测ID、节点ID、原始值/类别值、主观分、备注
RuleVersion    规则版本：版本号、状态、发布时间、来源、说明
RuleNode       规则节点：版本ID、节点ID、父节点、权重、计入父项、证据等级
RuleMapping    规则映射：版本ID、映射ID、类型、锚点/区间/类别值
SyncQueue      同步队列：本地草稿ID、操作类型、创建时间、状态
```

关键约束：

1. `Evaluation` 必须绑定 `ruleVersion`。
2. `EvaluationItem` 只保存输入，不保存计算结果；总分由评分核心按规则重算。
3. 若需要缓存结果，必须另建 `EvaluationResultCache` 并记录输入哈希和规则版本。
4. 同一产品可有多条 `Evaluation`，支持固件/批次/复测。
5. 对比接口只允许在明确选择“跨版本对比”时混用版本。

## 4. 同步流程

```text
本地录入 -> 本地草稿 -> 校验 -> 待同步队列 -> 联网批量上传
                                            -> 服务端二次校验
                                            -> 创建 Evaluation / EvaluationItem
                                            -> 返回评测 ID
                                            -> 本地状态置为已同步
```

冲突处理：

- 本地未同步评测使用本地 UUID，服务端幂等接收。
- 若服务端已存在同 ID，比较内容哈希；一致则忽略，不一致则提示人工确认。
- 删除操作进入回收站状态，不做物理删除。

## 5. 接口草案

| Method | Path | 用途 |
|---|---|---|
| `GET` | `/api/rules` | 读取规则版本列表 |
| `GET` | `/api/rules/:version` | 读取规则树、映射和阈值 |
| `POST` | `/api/rules/:version/publish` | 发布新规则版本 |
| `POST` | `/api/rules/:version/rollback` | 将某版本标记为回档版本 |
| `POST` | `/api/evaluations` | 创建或幂等更新评测 |
| `GET` | `/api/evaluations` | 分页查询历史评测 |
| `GET` | `/api/evaluations/:id` | 读取评测、输入和规则版本 |
| `POST` | `/api/evaluations/:id/recompute` | 使用指定规则版本重算 |
| `POST` | `/api/sync` | 批量同步待同步队列 |

## 6. 规则版本生命周期

```text
Draft -> Review -> Published -> Deprecated
                         |
                         +-> RolledBack
```

规则：

- `Draft` 可修改，不参与正式计算。
- `Published` 不可修改；需要调整时创建新 Draft。
- 历史评测可固定在任意已发布版本。
- 回档本质上是“把默认版本指针指向旧版本”，不是改写旧版本内容。
- 每次规则发布必须附带基准集验证报告。
